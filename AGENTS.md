# AFIKA POS (`app/afika-pos`)

Expo (React Native) point-of-sale app. Bundle id `phumzile.afika.pos`, scheme
`afika`, Expo Router with typed routes. All app code lives in `src/`; the `@/*`
path alias maps to `src/*` (see `tsconfig.json`, `jest.config.js`).

## Layout

- `src/app` — routes. `index.tsx` boots to `onboarding` when no `business` row
  exists, otherwise to `(tabs)`. Tabs: Sell, Products, Stock, History,
  Insights, Wallet. `cart.tsx` → `checkout/[id].tsx` (QR + share link +
  polling) → `sale/[id].tsx` (receipt).
- `src/domain` — pure, dependency-free logic (money, cart, discount, loyalty,
  payment options, receipt formatting). Unit tested with Jest.
- `src/services` — SQLite-backed use cases. Every function takes a `PosDb`
  (`src/db/types.ts`) so the same code runs on `expo-sqlite` and in tests.
- `src/db` — Drizzle schema, `bootstrap.ts` (DDL), `client.ts`, `seed.ts`
  (optional demo data, not called at start-up).
- `src/state`, `src/store`, `src/hooks`, `src/ui`, `src/theme`, `src/lib`.
- `src/assets` — icons and the payment asset SVGs.

## Commands

```bash
yarn install
yarn test           # Jest (node environment, babel-preset-expo transform)
yarn typecheck      # tsc --noEmit (also regenerates nothing; see below)
npx expo start --localhost
npx expo run:ios    # Debug dev-client build into the booted simulator
yarn e2e            # Maestro: onboarding, add-product, sell
```

Typed routes are generated by Metro into `.expo/types/router.d.ts`. If `tsc`
reports unknown routes after adding/removing a screen, run `npx expo start`
once and re-run `yarn typecheck`.

## End-to-end tests

`scripts/e2e.sh [flow ...]` picks the booted iOS simulator (override with
`MAESTRO_DEVICE`), wipes **only** `Documents/SQLite/crypto-pos.db*` in the app
container and runs Maestro with `--device`.

- Debug builds are an Expo development client, so the flows start the app with
  `openLink` (`afika://expo-development-client/?url=<metro>`) instead of
  `launchApp clearState`, which would drop the packager URL. Metro must be
  reachable at `METRO_URL` (default `http://localhost:8081`).
- `MODE=release scripts/e2e.sh` launches the plain app scheme instead.
- `RESET_DB=0` keeps the database between runs.
- Flows: `.maestro/onboarding.yaml`, `add-product.yaml`, `sell.yaml`; shared
  steps live in `.maestro/subflows/` (`start-app`, `complete-onboarding`,
  `create-flat-white`).
- Keyboard notes: `hideKeyboard` is unreliable here and the numeric keypad has
  no dismiss key, so the product form uses `keyboardDismissMode="on-drag"` and
  the flows swipe between fields. Otherwise the next tap hits a keypad button
  and types into the previous field.

## Online payments

- `src/services/payments.ts` creates a local `pending` sale plus a
  `payment_requests` row and POSTs to `backend/api` (`/v1/pos/payments`). The
  API returns the shareable `/pay/{id}` URL shown as a QR code.
- `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_API_TOKEN`, `EXPO_PUBLIC_CHECKOUT_URL`
  configure the API (see `.env.example`). Without a reachable API the flow
  still works offline: the request is stored locally and the checkout screen
  offers **Simulate payment (demo)**.
- `backend/workers/receipt` watches the chain and confirms the payment; the app
  polls and then settles the sale exactly once (`settlePayment`).
- Payment options and the demo ZAR rates are duplicated in three places that
  must stay in sync: `src/domain/payment.ts`, `backend/api/lib/payments.go`
  (`posAssets`), `backend/workers/receipt/lib/match.go`.

## Conventions

- Money is integer ZAR cents; use `src/domain/money.ts` for parsing/formatting.
- Business onboarding is DB-driven (not gated on Privy sign-in). Merchant name,
  website and address are printed on every receipt and sent with each payment.
- Never import from outside `src/` in app code, and do not re-add the old
  `app/afika` trading screens (send/trade/stocks); this app is a POS.
